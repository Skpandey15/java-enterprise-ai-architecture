# Part 4 — Database

This part covers vendor-neutral SQL and relational design, PostgreSQL, MongoDB, schema evolution, indexing, transactions, consistency, caching, partitioning, replication, high availability, recovery and distributed-data patterns.

## Featured learning track

- [Database: Zero to Expert](database-zero-to-expert/README.md) — thirteen progressive, hands-on chapters from database fundamentals and SQL through joins, PostgreSQL performance, NoSQL, high availability and expert system design.
- [SQL JOINs: Zero to Expert](database-zero-to-expert/13-sql-joins-zero-to-expert.md) — dedicated vendor-neutral coverage of join types, cardinality, nulls, semi/anti joins, physical algorithms, indexing, plans and ORM behavior.

## Architecture guides

- [Saga and Transactional Outbox](saga-and-transactional-outbox.md)
- [ADR-0001: PostgreSQL as the System of Record](../../adrs/0001-postgresql-system-of-record.md)

## Recommended path

1. Complete Chapters 1–3 for relational foundations, SQL and modelling.
2. Study Chapter 13 after Chapter 2 for the full SQL JOINs track.
3. Build the PostgreSQL lab in Chapters 4–8.
4. Add scale, NoSQL and operational capability in Chapters 9–11.
5. Complete the distributed-data capstone in Chapter 12.
6. Use the Saga/Outbox guide and ADR as architecture companions.

## Target capability

The learner should be able to design a correct schema, write and tune vendor-neutral SQL and joins, control concurrency, evolve production data safely, choose SQL versus NoSQL from evidence, plan HA and recovery, and defend distributed-data trade-offs in a senior system-design discussion.
